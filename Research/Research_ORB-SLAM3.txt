Research on ORB-Slam3

Tracking module (9:13 PM 10/14/2026)

	-Computes current frame pose in the active map in real time
	-Decides whether to insert current frame as a keyframe
		. A keyframe is basically an important frame pretty much
	-Adds inertial residuals into the optimization to estimate rigid body velocities and IMU biases
	-Tracking lost = Attempt to relocalizate
		. if succeds = tracking recovered and the active map is switched if necessary
		. if unsuccessful after a bit = current active map is stored as inactive map and a new map is reinitialized.


Local mapping module (9:58 PM 10/14/2026)
	
	-Adds keyframes and map points to the current active map
		.Map points are 3D landmarks in the active map
	-Removes redundant frames (extra unneeded frames)
	-Optimizes map using visual bundle ajustment or visual inertial bundle adjustment over the neighboring keyframes of the current frame.
		.Bundle adjustments enchance accuracy and reliability of 3D scene reconstructions from multiple images and camera views
	-Uses maximum MAP estimation to initialize and optimize IMU parameter in inertial mode

Loop and map merging module (10:16 PM 10/14/2026)
	
	-Detects shared regions between the active map and whole Atlas (All of the active maps) whenever a new keyframe is added.
	-If shared regions are part of the active map a loop correction is performed
	-If it belongs to another map then both active maps and the other map are fused into one map and that fusion becomes the new active map
	-Seperate thread runs global bundle adjustment after the loop correction to optimize the map but not affect the real-time performance

Atlas module (10:18 PM 10/14/2026)

	-Multi-submap system composed of a set of discrete maps
	-Maintains one active map that is being used for tracking while the local mapping thread continues to optimize and update that map with new keyframes
	-Other maps are inactive maps
	-Builds a database of keyframe information based on a BoW model to relocate, detect loops and merge maps

Pose estimation by fusing IMU and camera data (10:49AM 15/10/2026)
-IMUs measure angular velocity and linear acceleration but have a lot of drift
-Just double IMU data integration unreliable for long-term pose estimation
-IMUs are better for short-term pose estimation during fast motions (which was bad for cameras since fast paced movement makes motion blur which is bad for estimating poses) 
-IMUs can maintain acceptable pose estimates when cameras are unreliable
-Camera data has negligible drift so images can correct the IMU drift and keep the estimated poses accurate
-Pure visual SLAM struggles with dynamic obstacles
-IMU senses the platform motion directly which partially mitigates the impact of dynamic objects


Main steps of pose estimation (10:56AM 15/10/2026):
-Get the images and inertial measurements from the IMU (IMU sampling rate > camera sampling rate)
-Extract feature points from the camera frames
-Compute descriptors for the features and match them together 
  .Optical flow tracking may also be used as an alternative (kind of how a mouse works)
-Integrate the IMU measurements to calculate the relative position and velocity between two frames for those IMU measurements
-IMU initialization (method used by ORB-SLAM3).

Methods of tracking (11:04AM 15/10/2026):

.Vision-only - Classic ORB-SLAM with keyframe rates of 4hz for 2 seconds to get a scaled map that typically includes around 10 keyframes and hundreds of map points and then refine with visual-only bundle adjustments.
(Basically camera only)

.Inertial-only - Estimate optimal IMU parameters using the data from the monocular visual SLAM initialization and the IMU measurements between keyframes. Parameters include scale factor, gravity direction, IMU sensor biases and unscaled velocities of keyframes. These measurements form a state vector used in an optimization problem. Once the optimization is complete everything (frame poses, velocities and 3D map points) are scaled by the estimated scale and rotated so the z axis aligns with the estimated gravity direction.

Strengths, weaknesses, and improvement opportunities of the feature-based tracking module (11:13 PM 10/15/2026)

	-Extracts feature points and matches descriptors
	-Drawbacks:
		:time-consuming
		:Motion blur leads to inaccuracy on pure visual
		:Cannot obtain enough key features in textureless environments (Pure visual SLAM)
		:Alternative approach (combining feature extraction with optical-flow tracking) makes global map construction harder and still requires the separate feature extraction/descriptors for the loop closure and relocalization
	-Visual-inertial uses IMUs which makes it easier to extract features with the same performance as the cameras but with added inertial measurements to mitigate mistakes in high motion situations
	-ORB-SLAM3 Introduces the Atlas system in case of the tracking being lost
	-If tracking is lost the current frame queries the Atlas database to see the last keyframes across all maps
